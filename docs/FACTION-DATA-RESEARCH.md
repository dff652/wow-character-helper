# 阵营比例与建号阈值可行性 · 2026-11-08

## 结论

显示比例、配置阈值和按条件触发尝试在程序层面可实现，但本轮没有找到已核实可用的国服无限 PvP 实时阵营比例数据源，也没有找到官方公布的建号放行比例。当前不能交付可靠的“比例达到阈值便可建号”功能。

应按地区、游戏版本和规则集区分数据。无限使用规则集，不能把旧版单服人口表或欧美、台服比例当作国服 PvP 数据。

## 调研依据

1. [国服官方：规则集由你定](https://wow.blizzard.cn/news/24302070/)确认 PvP 阵营人口失衡时限制该阵营新建角色，但这份公告没有给出百分比阈值、统计时间窗或人口计数口径。不能自行认定为 50%、55% 或当前在线人数。
2. [API 库作者的实测记录](https://us.forums.blizzard.com/en/blizzard/t/wow-forever-api-what-works-so-far-plus-a-ts-client/60334)列出规则集 API `/data/wow/ruleset/{id}`，报告返回 id、name、auctions、status，没有提供阵营计数或建号解锁字段。这是作者在暴雪论坛发布的第一手记录，不是暴雪正式接口承诺；作者明确称接口尚未正式文档化。国服还需独立验证。本轮未持有开发者凭据、未调用国服认证 API，不应宣称已经穷尽所有接口。
3. [WoWCensus 的 Forever 页面](https://wowcensus.io/forever/)明确表示数据来自游戏内 /who 样本，是观察到的角色数，不是独立玩家总数或实时在线人口。[规则集分组页](https://wowcensus.io/forever/realms)也说明按地区和类型合并采样。
4. [Forever Relationships 作者的更新说明](https://www.curseforge.com/wow/addons/forever-relationships/files/9476601)提供阵营比例显示，但数据是插件用户遇到的角色样本；伴随程序每小时刷新，游戏端在登录或重载后显示新数据。这证明样本比例面板可实现，不能证明国服完整覆盖或分钟级建号判定可靠。

## 可选路线

| 路线 | 可获得什么 | 对本工具的意义 |
|---|---|---|
| 官方公开 API | 已有社区记录的规则集、角色等数据；未核实比例接口 | 优先寻找，必须验证国服返回字段及口径 |
| 第三方普查 API / 数据导出 | 采样角色中的阵营占比 | 有国服同规则集覆盖及可用接口后可接入，明确标为样本 |
| 自建游戏插件采样 | 自身可见范围或查询结果中的角色 | 仍是样本；需要已有角色登录，不能凭此直接获知服务器锁定计数 |
| 游戏画面识别 | 页面实际展示的提示和建号提交结果 | 现有工具已经识别已知阵营限制提示；未发现百分比显示，OCR 无法产生不存在的数据 |

角色资料、拍卖行数量与全量人口不是同一个统计对象。把它们汇总成比例，也不能自动等同于建号限制的分母。读取客户端内存或网络消息是否能取得该数值也未经证实；不能假定服务器会把内部统计下发给客户端。本方案无需大模型 API。

## 建议的页面和行为

先显示可证实的信息：地区 / 规则集、目标阵营、最近一次提交结果及时间、连续拦截次数、下次尝试倒计时。状态措辞应为“上次提交受限”，而不是把两分钟前的结果描述为当前实时锁定。没有比例数据时显示“暂无数据”，不能显示 0% 或推测值。

以后接入数据源时，比例面板必须同时记录联盟数、部落数、分母口径、统计时间窗、采集时间、来源、样本规模以及地区 / 规则集。联盟与部落需为同一采样窗口，地区或规则集不匹配时不得参与任务判断。

阈值模式默认关闭，条件可设计为“目标阵营样本占比 ≤ 用户阈值，且数据在有效期内、样本满足要求、连续若干次新采样达标”。重复读取同一份旧快照不能计作多次新采样。满足条件只能触发一次现有建号尝试，不能标记服务器已经放行；服务器拒绝时仍按既定间隔等待并刷新规则集。

数据缺失、过期或请求失败时，阈值任务进入等待数据状态。是否回退到原有定时尝试应单独配置，不应静默回退。显示采样趋势可以作为参考，不建议用第三方样本充当必须低于 50% 才允许尝试的硬条件，否则可能错过实际开放窗口。

## 当前交付范围

本次为资料调研和现有代码核对，未修改运行逻辑、未安装插件、未接入任何比例接口、未提交建号。当前执行器只识别已知阵营限制；未识别结果会留档停止，不能将“没有识别到限制”当作“可以创建”。

后续优先完成角色组合实际选中验证和完整执行流程，再增加“最近建号状态”面板。比例自动触发功能等待可靠国服数据源验证后接入。
